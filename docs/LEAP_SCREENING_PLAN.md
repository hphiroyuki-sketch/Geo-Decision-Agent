# 簡易スクリーニング（TNFD LEAP準拠）実装計画

用途：**企業へのデモ時に、その企業の拠点について一次スクリーニングを提示する。**
出力：画面 ＋ PDF／ドキュメント。

---

## 1. 調査結果：LEAPの正確な構造

TNFDのLEAPは「スコーピング」に続く4フェーズ・**16コンポーネント**で構成される。
本実装はこの構造をそのまま採用する（独自の4分類ではなく、TNFDのコード体系に合わせる）。

### スコーピング（LEAP開始前）
仮説の構築、対象範囲・バリューチェーンの範囲、必要な資源の見積り。

### Locate — 自然との接点を特定する

| コード | 名称 | 導きの問い |
|---|---|---|
| L1 | Business footprint（事業のフットプリント） | 直接操業する資産・拠点と、関連するバリューチェーン（上流・下流）の活動はどこにあるか |
| L2 | Nature interface（自然との接点） | それらの活動はどのバイオーム・生態系と接しているか。各地点の生態系の**完全性（integrity）と重要性**は現在どうか |
| L3 | Priority location identification（優先地域の特定） | 高い生態系完全性を持つ地域、完全性が急速に低下している地域、生物多様性上重要な地域、水ストレス地域、重大な依存・影響が想定される地域は、どこにあるか |
| L4 | Sector identification（セクターの特定） | それらの優先地域で自然と接しているのは、どのセクター・事業単位・バリューチェーン・資産クラスか |

### Evaluate — 依存と影響を診断する

| コード | 名称 | 導きの問い |
|---|---|---|
| E1 | Identification of relevant environmental assets and ecosystem services | 各優先地域でどの事業活動が行われ、どの環境資産・生態系サービスに依存／影響しているか |
| E2 | Identification of dependencies and impacts | 各優先地域で、どのような自然関連の依存と影響があるか |
| E3 | Dependency and impact measurement | 依存の規模と範囲、負の影響の深刻度、正の影響の規模と範囲はどれほどか |
| E4 | Impact materiality assessment | どの影響が重要（material）か |

### Assess — リスクと機会を評価する

| コード | 名称 | 導きの問い |
|---|---|---|
| A1 | Risk and opportunity identification | 対応するリスクと機会は何か |
| A2 | Existing risk mitigation and management | すでに適用している低減策・管理手法は何か |
| A3 | Risk and opportunity measurement and prioritisation | どのリスク・機会を優先すべきか |
| A4 | Risk and opportunity materiality assessment | どれが重要であり、TNFD推奨開示に沿って開示すべきか |

### Prepare — 対応と開示を準備する

| コード | 名称 | 導きの問い |
|---|---|---|
| P1 | Strategy and resource allocation plans | この分析の結果、どのようなリスク管理・戦略・資源配分の意思決定を行うか |
| P2 | Target setting and performance management | どう目標を設定し、進捗をどう定義・測定するか |
| P3 | Reporting | TNFD推奨開示に沿って何を開示するか |
| P4 | Presentation | 自然関連開示をどこで、どのように提示するか |

### 優先地域（priority locations）の定義

優先地域＝**重要地域（material locations）** ＋ **感度の高い地域（sensitive locations）**。
感度の高い地域は5つの特性で判定する：

1. 生物多様性にとって重要な地域
2. 生態系の完全性が高い地域
3. 生態系の完全性が急速に低下している地域
4. 物理的な水リスクが高い地域
5. 生態系サービス供給上、重要な地域

### 関連する前提

- TNFD提言＝4つの柱（ガバナンス／戦略／リスクと影響の管理／指標と目標）と**14の推奨開示**。
- 対策の優先順位は緩和ヒエラルキー（IFC PS6由来）に基づく。SBTNはこれを**AR3T**（Avoid／Reduce／Restore／Regenerate／Transform）として整理している。本製品は要件定義書に従い「回避→低減→回復→オフセット」を主軸に置きつつ、AR3Tとの対応を併記する。
- 日本ではSSBJ基準が2027年3月期からプライム上場・時価総額3兆円以上に段階適用（2026年3月期から任意適用）。現時点で確定しているのは気候関連であり、自然関連はTNFD提言の活用が示されている段階。

## 2. 本システムが実際に「証拠を出せる」範囲

**これが計画の核心である。** LEAPの体裁だけ整えて中身を推定で埋めれば、開示に使えないどころか有害になる。
本システムが衛星・現地データで実際に裏付けられるのはLocateの一部に限られる。以下を製品仕様として明示する。

| コンポーネント | 本システムの対応 | 根拠となるデータ |
|---|---|---|
| L1 事業のフットプリント | **対応** | 利用者が登録した拠点座標・面積 |
| L2 自然との接点 | **部分対応** | Google Satellite Embedding（64次元・10m・年次）とSentinel-2指標による**状態と変化の実測**。ただしバイオーム／生態系タイプの分類、公的な生態系完全性指標との照合は未接続 |
| L3 優先地域の特定 | **部分対応** | 5基準のうち「完全性が急速に低下している地域」は変化スコアで判定可能。「完全性が高い地域」は基準地点との類似度で相対的に判定。残る3基準（生物多様性重要地域・水ストレス・生態系サービス）は**公的データ未接続のため判定不可** |
| L4 セクターの特定 | **部分対応** | プロジェクトのユースケース区分のみ。バリューチェーン展開は対象外 |
| E1–E2 依存・影響の特定 | **未対応（構造のみ）** | セクター別の依存・影響マッピング（ENCORE等）は未接続。現地記録から確認種を列挙するに留まる |
| E3 依存・影響の測定 | **部分対応** | 影響側の面積・変化は実測可能。依存側（水源涵養・受粉等）は対象外 |
| E4 影響の重要性評価 | **未対応** | 重要性の判断は企業の閾値設定を要する |
| A1–A4 リスク・機会 | **部分対応（候補提示）** | スクリーニング結果から候補を提示。重要性判定は人が行う |
| P1–P2 戦略・目標 | **対応** | 区域別の回復計画（施策・指標・頻度・責任者）を生成 |
| P3–P4 報告・提示 | **対応** | 本スクリーニング帳票、意思決定レポート |

**したがって本機能の名称は「簡易スクリーニング（Locate中心）」とし、
「TNFD開示そのもの」ではなく「LEAPのLocateを衛星データで前倒しし、E以降の作業範囲を確定させるもの」と位置づける。**

## 3. 実装内容

### 3.1 LEAPモデルの作り直し（worker/src/lib/leap.ts）
- スコーピング＋16コンポーネントを正式なコード・名称・導きの問いで表現。
- 各コンポーネントに `coverage`（`covered` / `partial` / `not_covered`）を持たせ、
  **何が言えて何が言えないか**を機械的に表示する。
- 根拠区分は既存の `measured` / `field_confirmed` / `estimated` / `missing` を継続。
- 感度の高い地域5基準の判定表を追加。判定できない基準は「データ未接続」と明示。

### 3.2 簡易スクリーニング帳票（新規）
1ページ目に結論、以降に根拠という順序（要件定義書のUX基準：結論→理由→次の行動）。

1. 表紙：対象企業・拠点数・実施日・分析ID・位置づけと免責
2. エグゼクティブサマリー：拠点ごとの判定と一行根拠
3. LEAP対応状況：16コンポーネント × 対応状況
4. Locate詳細：拠点ごとの衛星実測値・優先区域・変化
5. 感度の高い地域5基準スクリーニング（データ接続状況を明示）
6. 次のアクション：E以降に進むために必要なこと
7. データソース・前提・免責・再現情報

### 3.3 出力
- **PDF**：A4印刷用CSSを持つ帳票画面をブラウザ印刷でPDF化（Workersの10ms CPU制約下でサーバ側PDF生成は非現実的なため）。
- **ドキュメント**：Markdownをダウンロード。顧客の資料へ貼り付けて編集できる。

### 3.4 複数拠点
1プロジェクト内の複数拠点（候補地・メッシュ）を横断して1つの帳票にまとめる。

## 4. 検証（納品前）

- [ ] 16コンポーネントのコード・名称・問いがTNFDの定義と一致しているか
- [ ] 「対応」と表示している項目に、実際に裏付けデータがあるか
- [ ] 推定値・未接続を実測値として提示していないか
- [ ] A4印刷でレイアウトが崩れないか（実ブラウザで確認）
- [ ] 免責（法定アセスの代替ではない／一次スクリーニングである）が表紙と各所にあるか
- [ ] 企業名など未入力の場合に体裁が崩れないか
