## 総合判定：**条件付き合格**

顧客に見せられる状態には達している。ただし**納品前に確認・合意が必要な項目が4件**ある（第4章）。
これらは「動かない」ではなく「まだ確かめていない」または「顧客のデータ提供待ち」であり、
隠さず提示したうえで判断を仰ぐべき性質のものである。

### 合格と判断した根拠

1. **中核機能が実データで動作している。** Google Earth Engine から実際に取得した衛星エンベディングが
   本番DBに 764 件キャッシュされ、800 セルのメッシュが実測値で分類されている。シミュレーションではない。
2. **数値の出所が常に明示されている。** 全画面で実データ／現地確認済み／推定／未取得を区別表示しており、
   検証不能な数字を提示していない。
3. **専門知識がなくても読める。** 用語にはその場で説明が出る。空の画面には必ず次の行動が書いてある。
4. **危険な設定を事前に止める。** 数分かかる処理の前に条件の妥当性を検査し、無意味な実行を警告する。

## 3. 意図的に「やらなかった」こと

顧客提示時に説明できるよう記録する。

1. **設備台帳の数字を作らなかった。** 要件定義書 V-06 の図には「監視設備 12,480」等の数字があるが、
   設備データを保有していない以上、それらしい数字を表示することは顧客を欺くことになる。
   代わりに実際に保有する行数（監視セル数・区域面積等）を数えている。
2. **データの無い開示項目を埋めなかった。** TNFD出力では未取得項目を「未取得」と表示し、取得方法を併記した。
   不完全な開示よりも、創作された開示のほうが有害であるため。
3. **法令適合性を判定しなかった。** 環境アセスメントや林地開発許可の要否は、
   専門家・行政窓口の確認事項として明記するに留めた。

## 4. 納品前に確認・合意が必要な項目

### 4-1. 衛星指標（NDVI等）のクエリ疎通【1件修正済み・再確認待ち】

自己診断が本番で実行され、状況が確定した（2026-09-01 22:04 / 22:14）。

| チェック | 結果 |
|---|---|
| 衛星エンベディング取得 | **ok（64次元）** — メッシュ・類似度・変化検出は実データで稼働 |
| 植生指数（NDVI等）取得 | 失敗 → `Unknown function: 'Collection.filterBounds'` |

`filterDate` と同種の誤りで、`filterBounds` もサーバー側関数ではなかった。
`Collection.filter` ＋ `Filter.intersects`（`.geo` との交差）へ置換し、デプロイ済み（run 38）。

**再確認方法:** アプリを開き、管理設定画面の「衛星データ連携の稼働状況」を見る
（アプリ利用中に10分間隔で自動実行される。「今すぐ確認」でも実行可）。
**失敗が続く場合:** エラー文が次の不正な関数名を示すため、同じ手順で潰せる。
**影響範囲:** 指標欄が空欄になるのみ。他機能は影響を受けない。

### 4-2. 定期実行（cron）が発火していない【回避策あり】

5分ごとの自動診断・アラート判定を設定し、デプロイ時に登録も確認できた（`schedule: */5 * * * *`）が、
実際には一度も実行されていない。原因は特定できていない（Cloudflare側の設定または無料プランの制約の可能性）。

ハートビート行すら記録されないため、トリガー自体が実行されていないと確定した。

**回避策は動作実証済み:** アプリを開いている間の定期通信に自己診断とアラート判定を相乗りさせており、
本番で実際に実行された記録がある（22:04 / 22:14）。**利用中は10分ごとに実行される**。
実運用上の支障はないが、誰も開いていない間は動かない。
**恒久対応:** Cloudflare ダッシュボードで Cron Triggers の状態を確認する。

### 4-3. 公的データ未接続【顧客合意が必要】

保護区域・急傾斜地・流域界・土地被覆はシミュレーション値である。画面上で「推定値」と明示しているが、
**実務判断に用いる前に公的データとの照合が必須**である。接続先データの選定と利用条件の確認が必要。

### 4-4. 地図タイルの商用利用条件【納品前に必須】

現在は国土地理院・Esri・OpenStreetMap の無償タイルを使用している。
社内実証では問題ないが、**商用提供時は各提供元の利用規約確認、または有償プランへの切替が必要**。
切替は `frontend/src/components/MapView.tsx` のURL定義1箇所で完了する設計にしてある。
