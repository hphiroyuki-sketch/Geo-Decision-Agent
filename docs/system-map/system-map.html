Geo Decision Agent ─ 何を組み合わせて動いているか

このシステムは、いくつかの会社や公的機関のサービスを“部品”として組み合わせて作っています。どの部品が何をしていて、どうつながっているかを1枚にしました。部品をクリックすると、中学生向けの説明と専門家向けの説明、根拠になったファイルが右に出ます。

① 家は Cloudflare画面・司令塔・データベース・写真の倉庫は、Cloudflare の計算機の上で動いています（無料プラン）。
② 目は Google の衛星、口は Claude土地を測るのは Google Earth Engine の衛星データ。結果を言葉にするのは Anthropic の Claude。
③ 裏づけは公的データ生き物の記録（GBIF）、災害リスク（国土地理院）、保護区（OpenStreetMap）で確かめます。

Google の「衛星エンベディング」って何？

このシステムの中心になる測り方です。1年分の衛星観測を、10m四方ごとに64個の数字の並び（指紋）にまとめたデータを Google が公開しています。似た土地は似た並びになるので、「現地で確認した生き物のすみか」と並びが似ているマスを探せます。

なぜ「指紋」で比べるのか

植物の量（NDVI）のような1つの見方だけだと、「緑が多い」ことしか分かりません。指紋は地形・水・植生・季節の変わり方などをまとめて表すので、「確認済みのすみかにどれだけ似た土地か」を測れます。

ただし似ていることは「いる」ことの証明ではありません。だから結果は「現地で確かめる優先順位」として出し、根拠区分（実測／推定）を必ず付けます。

植生指数（Sentinel-2）は補助線

欧州の衛星 Sentinel-2 の画像から、植物の量（NDVI）、葉の元気さ（NDRE）、水分（NDMI）、焼けや伐採の目安（NBR）を計算し、前年と比べます。

専門家向け：COPERNICUS/S2_SR_HARMONIZED の年間メディアンから4指数を1回の計算で取得（earthEngine.ts:330-342）。

部品何をしている？技術的には根拠

無料プランの制約と、そのための工夫

1回の処理は CPU 10ミリ秒まで

重い計算はできません。ハザードマップの画像は中身を開かず、「あるか（200）・ないか（404）」と大きさだけで判定します。

手元の開発環境はこの上限をかけないので、手元で動いても本番で落ちることがあります。

1回の処理で外部に頼めるのは50回まで

メッシュ解析は16マスずつ区切って何度も呼びます。一度取った衛星の値はデータベースにメモして、二度目からは聞きません。

最悪の場合で1回あたり約38回（16マス×2年＋お手本の作成＋認証）。

AIの料金は月 ¥5,000 まで

AIを使うたびに料金を記録し、月の合計が上限に届いたら AI を呼ばずに止めます。上限は設定画面で変えられます。

usage_log の当月合計で判定（routes/chat.ts:58-89）。

失敗を「なかった」にしない

外部のデータが取れなかったときは「取れなかった」と記録し、報告書には「判定不可」と出します。相手側の混雑と、こちらの不具合も分けて記録します。

public_data_cache.status = ok / failed / busy / empty。

専門家向け：文書とコードのずれ（直す候補）

棚卸しの途中で見つかった、説明とコードが食い違っている箇所です。隠さずに載せています。

  • 植生指数の計算で、コメントは SCL（雲などの分類）によるマスクに触れているが、式グラフに SCL の処理は無く、単純な年間メディアンになっている（earthEngine.ts:330-331）。
  • docs/ARCHITECTURE.md は「失敗したバッチは指数的に間隔をあけて再試行」と書くが、実装は 800ms×回数 の線形待ちで、3回続けて失敗したら止まる（MeshView.tsx:299-303）。
  • docs/ARCHITECTURE.md の外部呼び出し数（16×2＝32）は、お手本の作成（最大5回）と認証（1回）を数えていない。最悪で約38回だが、上限の50には収まる。
  • docs/EXTERNAL_SERVICES.md の GBIF の説明は IUCN 区分の集計だけだが、実装は種の数の集計（facet=speciesKey）も並列で呼んでいる。
  • Earth Engine への呼び出しには、タイムアウトと再試行がまだ無い（earthEngine.ts:127）。
