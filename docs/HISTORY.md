# 開発履歴と、実際に踏んだ不具合

**同じ罠を踏み直さないための記録。**
「なぜこの一見冗長なコードがあるのか」の答えは、たいていここにある。

コミット履歴は `git log --format='%h %ad %s' --date=short` で全55件見られる。
ここには**何を作ったか**と、**何が壊れていて、なぜ壊れていたか**を残す。

## 2. 実際に起きた不具合と、その根本原因

### 2.1 register / login が 500 を返した（8/31）

**症状**: 登録もログインもできない。
**原因**: **PBKDF2の反復回数が Workers 無料プランの CPU 10ms を超えていた。**
**対処**: 10,000反復に下げた。→ ADR-001

> **学び**: Workers では暗号処理の強度がCPU予算と直接トレードオフになる。

---

### 2.2 Earth Engine の式グラフを4回作り直した（9/1）

順に：

1. **リクエストの形が違った** — 式グラフ全体を `Expression` でラップする必要があった
2. **`filterDate` が存在しない** — サーバー側は `Collection.filter` を使う
3. **`Collection.filterBounds` が存在しない** — これもクライアントライブラリだけの名前
4. **年フィルタが効いていなかった** — 暦年でのフィルタに直した

**根本原因**: **`value:compute` はサーバー側関数名の完全一致を要求し、
Python/JSクライアントライブラリのメソッド名とは違う。** 推測で書くと必ず落ちる。

**対処**: `GET /api/admin/ee-algorithms?q=` を作り、
**EEが実際に公開している関数名と引数名を検索できるようにした。**
以後は推測せずここで確認する。

---

### 2.3 メッシュのオーバーレイが描画されない（9/1）

**原因**: MapLibre のスタイル式に `null` が混入していた。
**対処**: 式に入る値を必ず数値かフォールバック値にした。

---

### 2.4 3Dトグルが sky レイヤーで例外を投げた（9/1）

**対処**: sky レイヤーの追加をガードした。

---

### 2.5 地図が「自分のレイヤー設定を一度も適用しない」（9/5）★根本的

**症状**: 衛星画像もメッシュも表示されない。エラーも出ない。
**原因**: 待ち合わせに `map.isStyleLoaded()` を使っていた。

> **`isStyleLoaded()` は「すべてのソースキャッシュが落ち着いた」ときにしか true にならない。**
> この地図は10個のラスターソースを持つ。**1つでも決着しないソースがあると
> 述語は永久に false のまま**で、その後の処理が一切実行されない。

**対処**: `whenStyleReady` を、**目的のレイヤーが addressable になるまでポーリング**する形に変えた。

```ts
if (!map.getLayer("streets")) { timer = setTimeout(attempt, 100); return; }
```

**コード内にこの理由をコメントとして残してある。** → ADR-013

> **学び**: 「読み込み完了」を待つときは、**本当に必要な条件を直接聞く**。
> 総体的な準備完了フラグは、無関係な理由で永久に立たないことがある。

---

### 2.6 メッシュが 64/400 で止まり、ホットスポット0件（9/5）

**原因**: 1バッチの失敗でサンプリングループ全体が中断し、`analyze` が呼ばれなかった。
**成功にも失敗にも見えない状態**になっていた。

**対処**: 3回まで指数バックオフで再試行 → それでも駄目なら残りを諦め、
**`finally` で必ず `analyze` を呼ぶ** → 加えて「続きから再開」ボタン。→ ADR-014

---

### 2.7 基準地点が全部10m以内に固まっていた → 100%が保全優先（9/5）

**症状**: 全マスが `priority_a` になり、順位付けが意味をなさない。
**原因**: デモの現地記録が大阪の一点に集中していた。基準ベクトルが1地点しか表さない。

**対処**: 実測した距離つきの警告を画面に出し、地図上でピンを置き直す導線を作った。

---

### 2.8 東広島でスクリーニングしたら92%が「一般区域」（9/5）

**原因**: デモの基準地点が岐阜にあり、**対象地から400km離れていた。**
遠すぎる基準ベクトルとの比較は無意味。

**対処**: 上と同じ。地図上で基準点を指定できるようにした（`field_records.source = 'pin'`）。→ ADR-009

---

### 2.9 FR-022 が「実装済み」なのにどこからも呼ばれていなかった（9/2）★

**症状**: 分析結果画面の「環境変化(NDRE)」が乱数だった。
**原因**: `fetchSpectralIndices` を呼んでいたのは**定時自己診断だけ**。
`indices_cache` は一度も書かれていなかった。実際のコードは
`-1 * clamp(rng() * 18, 0, 18)` のままだった。

**対処**: `fieldData.ts` に `getSpectralIndices` / `getIndexChange` を作り、
`chat.ts` の分析経路から呼ぶようにした。画面に「実測／推定」を表示。

> **学び**: **「関数が存在する」と「呼ばれている」は別。**
> 機能の完了は、経路が実データを運んでいることまで確認して初めて言える。

---

### 2.10 設定値を「衛星実測」と表示していた（9/2）

**症状**: ユースケース名・対象年・メッシュ解像度・指標一覧まで「衛星実測」と印字されていた。
**対処**: 根拠区分 `configured`（登録・設定値）を新設して割り当て直した。→ `docs/DOMAIN.md` §5

---

### 2.11 帳票が自己矛盾した文を出した（9/2）

> 「類似度の最大値は 0.98 で、保全優先の判定基準 0.85 に届いていません」

**原因**: 条件分岐のガード漏れ。
**対処**: `simMax < stats.thresholds.priorityA` でガードした。

---

### 2.12 アプリのUIごと印刷され、改ページが効かない（9/6）

**原因**: **ブラウザは `overflow: auto` の内側でページ分割できない。**
**対処**: `.app-chrome` / `.app-shell` / `.app-main` にクラスを付け、
`@media print` でスクロールコンテナを解除しUIを隠す。

---

### 2.13 ダウンロードのファイル名が "download" になる（9/6）

**原因**: DOMに未挿入の `<a>` は `download` 属性を失う。
**対処**: `document.body.appendChild(a)` してからクリックする。

---

### 2.14 Overpass が本番で 521 → 429 / 429 / 429（9/6）

**原因**: **Overpass は送信元IP単位でレート制限をかけ、Cloudflare Workers は
プラットフォーム共有IPから外へ出る。** 我々のリクエスト量とは無関係に 429 になる。

**対処の変遷**（3段階）：
1. ミラーを3つにしてフォールバック → **解決しなかった**（構造的な問題なので当然）
2. 「混雑」状態を「失敗」と別に持ち、帳票では琥珀色で表示 → ADR-008
3. 定時診断も同じ関数で判定するよう統一

---

### 2.15 私自身の検証の抜け ── 正例しか確認していなかった（9/6）★最重要

**自分で見つけて直したもの。**

ハザード判定は「該当地で200・非該当地で404」に全面依存する。
そして私は**正例（東京都心）しか確認していなかった。**

> **どこでも200を返すサービスでも、そのチェックは緑になる。
> そして全拠点が「該当あり」と、企業に渡す文書に印字される。**

**対処**: 負例（富士山頂）を追加し、**両者を区別できなければ診断を失敗させる**ようにした。
本番実測は `該当地=200/3977B、非該当地=404` で判別可能を確認。→ ADR-006

> **学び**: **判別できないチェックは、チェックが無いより危険。**
> その結果は事実として引用されるから。
> 新しいデータ源を足すときは、必ず「該当する場所」と「該当しない場所」の両方で確かめること。

---

### 2.16 「busy」の判定ルールが2箇所で食い違った（9/7）

**症状**: 本番が `overpass-api.de: HTTP 521` を返し、書いたばかりのルール（429/504のみ）では
その事例自体が拾えなかった。しかもライブ取得と自己診断が**別々の条件**を見ていた。

**対処**: `isProviderSideStatus()` / `isProviderSideError()` に一本化。
429・5xx・タイムアウトは提供側、それ以外の4xx・DNS・パースエラーはこちら側。

> **学び**: 同じ判断を2箇所に書くと必ず食い違う。書いた直後でも。

---

### 2.17 デプロイでサービスアカウント鍵が黙って設定されなかった（9/1）

**原因**: ワークフローのシェルスクリプト内で `${{ secrets.… }}` を直接展開していた。
**鍵JSONはダブルクォート塗れなのでシェル構文が壊れ、その失敗が `if` に飲まれた。**

**対処**: すべて `env:` 経由で渡し、`printf '%s' "$VAR" | wrangler secret put …` にした。
`deploy.yml` にこの理由をコメントで残してある。

---

## 3. v3.0 要件の再監査（9/2）で見つかった5つの差分

1. **FR-022 が配線されていなかった** → §2.9
2. **再現情報が記録されていなかった**（FR-007 / NFR-010 / UAT-08）→ `analyses` テーブルを新設
3. **表示モードが無かった**（要件9章）→ かんたん／ビジネス／エキスパートを実装
4. **PWAでなかった**（5.1 / NFR-015）→ manifest・アイコン・Service Worker を追加。
   **API応答は意図的に一切キャッシュしない**
5. **信頼度の算出根拠が9.2の定義とずれていた** → 実測データ源の数で判定するよう修正

意図的に残した差分（対話からの書き込み系ツール、時系列グラフ、資料取込）は
`docs/REQUIREMENTS_COVERAGE.md` §6 に理由つきで記録してある。

## 4. この履歴から抽出できる原則

1. **「関数がある」≠「呼ばれている」。** 経路が実データを運んでいるところまで確認する
2. **判別できないチェックは、無いより危険。** 正例と負例の両方で確かめる
3. **総体的な準備完了フラグに頼らない。** 本当に必要な条件を直接聞く
4. **同じ判断を2箇所に書かない。** 必ず食い違う
5. **ローカルで動いても本番で落ちる。** CPU 10ms とサブリクエスト50は miniflare では強制されない
6. **失敗の握り潰しを疑う。** `|| true` と `if` に飲まれたエラーで、鍵が黙って未設定になった
7. **推定を測定と偽らない。** 出力が社外に出る以上、これが唯一の譲れない線
