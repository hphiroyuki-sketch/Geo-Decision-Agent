# 実操作評価と改善記録（2026-09-08）

## 評価

地図・チャット・現地記録・回復計画が同じプロジェクトにつながっている構成は残す価値があります。一方、今回確認した版を「現地調査相当の精度で種の存在を把握できる」「企業の立地判断にそのまま使える」と評価することはできません。10mメッシュの表示不具合だけでなく、候補地の総合スコアに仮値が混在し、種の検出精度の検証も未実施だからです。

今回の改善は、実データを見ながら現地調査の場所を検討する体験を成立させるものです。49ページの全要件の完成や、TNFD・自然共生サイト申請への適合認証を意味しません。

## 直した問題

| 観測した問題 | 改善 |
|---|---|
| 衛星写真は出るがGeoJSONメッシュは描画されない | MapLibre GL 6の別workerをViteで明示的に同梱。実際の描画数0→取得済み480マスが表示。その後、未取得も含む全1,600マスを描画 |
| 地図をドラッグすると元の場所へ戻る | 配列参照に依存したfitBoundsの再実行ループを修正 |
| 未取得部分が消え、失敗を再開できない | 全セルと取得状態を返す。失敗分だけを明示的に再キュー。全失敗を完了扱いにしない |
| 取得失敗も「取得済み」に加算 | 成功数のみを進捗に加算。取得途中の地図を定期更新。データ源が全面失敗すると早期停止 |
| 再解析で担当・進捗付き回復計画が消える | 担当・期限・進捗がある計画を409応答で保護。新メッシュで再評価する案内 |
| 10m中心点がキャッシュで同一化 | 座標丸めを4桁から6桁にし、旧キャッシュと識別。新規取得は隣接セルの衝突を回避 |
| 選んだマスをチャットに伝えられない | セル選択・強調・相談リンクを追加。サーバーで同じプロジェクトのセルを検証して保存値をAIへ渡す |
| スマホでレイヤーが地図を覆う | 小画面では初期折りたたみ。地図と条件・結果のタブ構成は維持 |
| 閲覧者でもAPIで変更できる | 認証以外の更新APIでviewerを403拒否 |
| 現地記録画面に位置関係が見える地図がない | 調査候補・登録記録・入力中の位置を地図で重ね、候補一覧は最大20件を表示 |
| 長時間の取得を途中で止められない | 取得結果を保存して一時停止する操作を追加。所要時間目安も実運転に合わせて調整 |
| 1,600マスを1件ずつDB更新して集計が重い | 区域への所属更新を80セルずつにまとめ、更新文を1,600件から20件へ削減 |
| 手入力座標をGPS精度0mで保存 | 精度不明をnullとして保存 |
| デモ基準点や同色メッシュを誤って説明 | デモを識別。類似度を生物の存在や保全価値と同一視しない説明へ変更 |
| 総合スコアの仮値が分かりにくい | ランキングとAIにデモであることを明示。未観測の現地記録数を生成しない |

10mは解析セルの公称間隔です。現行グリッドは緯度補正した経緯度格子で、GEEのネイティブ画素境界と完全一致する投影グリッドではありません。広域での面積計測・画素単位の厳密比較には、投影座標系とGEE transformを揃える次段階の実装が必要です。既存の保存メッシュは再計算していません。旧キャッシュで取得した値の精査は新しいメッシュで行います。

## 検証したこと

- `npm run test:release`: Worker型検査、フロント型検査・本番ビルド、20件の回帰テスト成功。
- テスト対象: workerアセットの実在と参照、10m間隔、入力不正、状態別GeoJSON、失敗再試行、管理済み計画の保護、viewer権限、キャッシュ精度。
- 本番D1コピーをローカル専用DBへ取り込み、ユーザー情報・認証を検証用に置換。メッシュ値を偽の色で補っていない。
- 実API: 1,600マス中480成功・1,120未取得を確認。EE未設定の1セル試験で、失敗→partial→再試行pendingを確認。
- Chrome: 全メッシュ、パン、セルクリック、数値表示、選択セルのAI相談画面への引き継ぎ、390px幅の地図を確認。
- ローカルではEE/Anthropicの秘密鍵を用いていない。上記ローカル検証のみで新規GEE取得・AI回答の本番成功を主張しない。

## 次の企業導入判断までに必要なこと

1. 仮値の残る総合ランキングを、由来・日付・空間解像度・欠損を持つ実データの評価へ置換する。保護区までの距離、アクセス、連結性、生息地重複は特に優先。
2. デモの観測と実際の現地記録を分け、対象企業の実在拠点・境界で試験する。現在の「広島県生物多様性調査」には岐阜のデモ基準地点があるため、そのまま顧客の分析結果として見せない。
3. 生物種ごとの検証用現地データで精度を測る。空間分割した検証、希少種の偽陽性・見逃し、季節差を評価する。環境embeddingのみから種の存在を確定しない。
4. 顧客・案件ごとのアクセス分離、監査ログ、担当者レビュー、希少種位置の公開範囲を設計して検証する。今回のviewer拒否だけで企業向け権限管理が完成したわけではない。
5. 現地調査計画の地図・チェックリスト・調査結果・回復施策の再評価をつなぐ。今回、添付概念図どおりの調査ルート自動作成は未実装。
6. 入力根拠と版が追跡できる帳票を専門家と受入評価する。既存レポートの仮値・デモを含む評価を申請根拠に転用しない。
