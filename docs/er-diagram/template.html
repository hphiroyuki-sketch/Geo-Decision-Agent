Geo Decision Agent ─ データの仕組み

このシステムが「何を、どんな順番で、どこに記録しているか」を1枚にまとめた図です。四角が「記録の表（テーブル）」、線が「つながり」。四角をクリックすると、中学生向けのやさしい説明と専門家向けの詳しい説明が右に出ます。

  • __S_TABLES__テーブル
  • __S_COLS__列
  • __S_FKS__外部キー
  • __S_MIGS__マイグレーション
はじめての人へ：この図に出てくる4つの言葉
テーブル（表）
同じ種類の記録を並べた表。Excelの1枚のシートのようなもの。図の四角1つが1つのテーブル。
列
表の見出し。「名前」「メール」のように、1行ごとに埋める項目。
外部キー
「この記録はあの記録のもの」という結びつき。存在しない案件に現地記録をぶら下げるといった矛盾を、データベース自身が止める。
キャッシュ
一度調べた答えのメモ。同じ場所・同じ年なら、衛星にもう一度聞かずにメモを使う。
実線：データベースが約束を守らせる“外部キー” 破線：つながっているが、約束は設けていない 点線：座標と年でメモを引く（キャッシュ） 矢印は「親 → 子」

この設計のポイント

図を見るだけでは分からない「なぜこう作ったか」です。出力は企業に渡すスクリーニング文書になるので、データの持ち方そのものが信頼性の条件になります。

1失敗も「事実」として残す

公的データに聞けなかったとき、「何もなかった」と書かずに「聞けなかった」と記録します。報告書では「判定不可」と表示されます。

専門家向け：public_data_cache.status = ok / failed / busy / empty。失敗は1時間、成功は30日で失効。

2推定を測定と偽らない

デモのデータ、地図上でクリックしただけの点、衛星が使えず推定で出した数字は、列で区別して、混ざらないようにしています。

専門家向け：field_records.demo / source、site_candidates.ndre_measured、analyses.earth_engine_available。

3あとから同じ結果を再現できる

AIの種類・ルールの版・使った衛星データの年を、分析のたびに記録します。「同じ分析ID＝同じ条件」と言えるようにするためです。

専門家向け：analyses（model / prompt_version / engine_version / earth_engine_year / inputs_json / replay_of）。

4「約束するつながり」と「引くだけのメモ」を分ける

案件とその記録は、データベースが整合性を守る強いつながり。衛星のメモは座標と年で引くだけなので、案件が消えても使い回せます。

専門家向け：embedding_cache / indices_cache / public_data_cache は (lat,lng,year) キーで外部キーなし。約100m丸めで近い拠点が同じ行を共有。
