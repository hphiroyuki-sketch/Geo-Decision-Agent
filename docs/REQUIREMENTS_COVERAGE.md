# 要件対応表（v3.0 要件定義書 ⇔ 実装）

判定基準:
- **実装** … 実データで動作し、画面から利用できる
- **部分** … 動作するが、データや範囲に制限がある（制限内容を明記）
- **未実装** … 着手していない（代替手段があれば明記）

「実データ」= Google Earth Engine から実際に取得した値。
「シミュレーション値」= 本MVPが決定論的に生成する仮の値。**画面上で必ず区別表示**している。

## 5. 既知の未確定事項（納品前に確認が必要）

1. **保護区域・急傾斜・流域界などの公的データ未接続** — 生息地重複度・保護区域距離・アクセスは
   現在もシミュレーション値。実務判断に使う前に、公的データとの照合が必須。
   （NDRE変化とAlphaEarth類似度は実測値になった。6軸中2軸が実測、4軸が推定という状態。）
2. **設備台帳（FR-040〜047 / V-07 / V-12）** — 設備データの提供を受けてから着手する。
3. **地図タイルの商用利用条件** — 現在は国土地理院・Esri・OpenStreetMap の無償タイル。
   商用提供時は各提供元の利用規約確認、または有償プランへの切替が必要。
4. **プッシュ通知・メール通知（FR-060 / 5.1）** — アプリ内通知は実装済み。
   端末プッシュとメール送信は送信基盤（VAPID鍵・メール送信元ドメイン）の決定待ち。

## 6. v3.0 再確認（2026-09-02）で見つかった差分と対応

要件定義書v3.0を全49ページ読み直し、実装と突き合わせた結果。

### 是正したもの

| # | 見つかった差分 | 対応 |
|---|---|---|
| 1 | **FR-022が配線されていなかった** — NDVI/NDRE/NDMI/NBRの取得処理は存在したが、呼んでいたのは定時自己診断だけ。`indices_cache` は一度も書かれず、分析結果画面の「環境変化(NDRE)」は乱数のままだった | 候補地ごとに当年・前年の指標を実取得してキャッシュし、NDRE変化を実測値として採用。表に「実測／推定」を表示。エキスパート表示で4指標の実測値を表示 |
| 2 | **再現情報（出力ブロック8 / FR-007 / NFR-010 / UAT-08）が無かった** — `analysis_id` は採番していたが、その分析が何を使ったかを記録していなかった | `analyses` テーブルを追加し、モデル・プロンプト版・判定ロジック版・衛星年・データセットID・EE接続有無・基準地点数・入力を記録。再現情報ブロックと判断履歴を表示 |
| 3 | **表示モード（9章）が無かった** — かんたん／ビジネス／エキスパートの3モードは要件本文にあるが未実装。FR-034の出し分けも未対応だった | 全画面共通の表示モード切替を追加。分析結果と意思決定レポートが、モードに応じて出す順序と粒度を変える |
| 4 | **PWAでなかった（5.1 / NFR-015）** — manifest・アイコン・Service Workerが存在しなかった | manifest＋アイコン＋Service Workerを追加。ホーム画面追加、新バージョン通知、オフライン表示、サインアウト時の端末データ消去に対応。API応答は意図的に一切キャッシュしない |
| 5 | **信頼度の算出根拠が9.2とずれていた** — 確認済み現地記録数だけで判定しており、「複数データが整合するが現地確認が不足＝中」という定義が反映されていなかった | 実測データ源の数（EE埋め込み／NDRE実測）を数え、9.2の定義どおりに 高／中／低 を決める |

### 未是正（意図的に残しているもの）

| # | 差分 | 判断 |
|---|---|---|
| 6 | **AIが呼べるツールが1つだけ** — FR-004とUC-02〜UC-10は、対話からメッシュ解析・変化検知・調査計画作成などを起動できることを想定している。現状は `analyze_site_candidates` のみで、メッシュ結果は読み取り専用のコンテキストとして注入している | 対話からの読み取りは成立している。書き込み系ツールの追加は、誤操作時の取り消し設計とセットで行うべきなので分けた |
| 7 | **V-09の時系列グラフ** | 変化の検出と履歴保持は実装済み。折れ線グラフは未実装（航空写真の年代スライダーが同じ問いに視覚的に答えている） |
| 8 | **FR-010〜014 の資料取込・文書検索・版管理（8章 ナレッジライブラリ）** | 現地写真のみ実装。PDF/Excel/GeoJSON取込と社内文書のハイブリッド検索は未着手。ここはRAG基盤を1つ増やす規模なので、他の是正と同じ回には入れていない |
