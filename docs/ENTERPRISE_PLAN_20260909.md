# ForestScope / Geo Decision Agent 企業提案に向けた改善計画

作成: 2026-09-09。実装前の計画。検証結果は末尾に追記し、計画と実績を区別する。

## 1. 達成したい顧客の仕事

対象拠点を選び、衛星で調査候補を絞り、現場の写真・記録で確かめ、回復活動と担当・期限を決め、その根拠を開示・申請準備に再利用する。商談ではこの一連を顧客の拠点で説明できる状態を目指す。衛星の環境類似度を種の生息確率や生物多様性の高さと同一視しない。現地調査同等の精度は、実地検証なしには保証しない。

## 2. 調査から分かったこと

### 公開情報で確認した事実

- バイオームはTNFD支援、自然共生サイト認定支援、調査内製化などを提供している。[企業向けサービス](https://biome.co.jp/for-companies/)。BiomeSurveyはスマホ撮影・AI同定・記録の内製化を支援する。[生物調査の内製化](https://biome.co.jp/services/biological-survey/)。写真判定やレポート生成だけを独自性とはしない。
- KDDIは、自社事業に適した分析項目の選定を課題とし、シナリオ分析を追加している。[KDDI TNFD第3版](https://news.kddi.com/kddi/corporate/csr-topic/2025/03/31/7620.html)。したがって「地図がきれい」だけでなく、拠点分析を事業判断に結びつける必要がある。
- NECはTNFD報告を継続し、AIによる報告業務支援も発表している。[NEC報告](https://www.nec.com/en/press/202509/global_20250929_03.html)、[NECのAI活用](https://www.nec.com/en/global/corporateblog/202506/02.html)。AI文章生成だけでは差別化しにくい。
- 東急建設は優先地域の選定、依存・影響、シナリオ、指標を開示し、上流資材の調達地域特定の難しさにも触れている。[TNFD開示](https://www.tokyu-cnst.co.jp/sustainability/environment/tnfd/)。拠点と調達先、実測と代替情報を分けて説明する必要がある。
- 王子グループは航空写真と現地確認を組み合わせた湿地再生、施業前後の継続モニタリングを報告している。[TNFD 2025](https://www.ojiholdings.co.jp/uploads/sustainability/docs/TNFDReport_2025_ja.pdf)。活動前後の証拠と効果確認が重要なユースケースになる。

これらから導いた課題は仮説であり、各社の予算、購入意向、当製品への評価を聞き取った結果ではない。

### メンタリング記録からの示唆（非公開の参考資料）

提供されたメモから、回復活動の費用・時間、継続的な現地記録、証拠の追跡性、大きな将来像と実証の段階分けを重視する。競合が回復策を十分提供できないという当時の発言は、現在の機能不足の証明ではない。位置情報やファイルハッシュだけで現地で撮影された事実を保証することもできない。メモの個人的背景や社内資金情報は製品へ転載しない。

### 制度との対応

TNFDは4本柱・14推奨開示であり、LEAPの拠点スクリーニングだけで開示全体は完成しない。ガバナンス、財務影響、シナリオ、バリューチェーン、指標・目標などの企業情報が別途必要。[TNFD提言](https://tnfd.global/recommendations/)。

自然共生サイトは2025年4月に法に基づく制度へ移行。現行様式、区域、権利者の同意、実施計画等を確認する。[環境省](https://policies.env.go.jp/nature/biodiversity/30by30alliance/kyousei/)、[ERCA申請](https://www.erca.go.jp/nature/nintei.html)。認定後は活動・モニタリングの定期入力が案内され、計画期間の延長は変更認定として扱われる。[ERCA認定後](https://www.erca.go.jp/nature/henko.html)。一律の旧制度の更新周期はハードコードしない。本アプリの出力は準備資料とし、公式様式への転記・審査・提出は区別する。

## 3. 課題 → 機能 → 完了条件

| ID | 担当者の課題・目的 | 対応する機能 | 受入条件 |
|---|---|---|---|
| P01 | 経営者へ地球全体と自社拠点の関係を直感的に伝えたい | 3D地球儀と拠点への移動 | 3Dで広域に引くと球体、拡大すると既存10mメッシュを表示。2D切替と選択を維持 |
| P02 | 写真・種名・同定根拠が別々で信頼性を判断できない | 地図上の生物カード、メディア・分類・確認状態 | 暗い画面でも可読。写真を優先表示。図鑑画像と現地写真、デモと観測を区別。未知の分類・希少性・精度を捏造しない |
| P03 | AIの説明が読みにくい | 安全なMarkdown表示 | 太字、箇条書き、表、コード、リンクを表示。HTMLや危険なURLを実行しない |
| P04 | 何を調査すれば開示できるか分からない | 開示・申請準備の項目別ワークスペース | 各項目の本文、根拠、担当・期限・状態を保存・再読込。未対応項目を把握し、下書きを持ち帰れる |
| P05 | 認定取得後の継続・変更に備えたい | 自然共生サイト準備・モニタリング項目 | 区域・同意・活動・指標・周期・実績・変更判断を整理し、公式案内へたどれる。自動認定を示さない |
| P06 | 提案された回復策を実行につなげたい | 既存回復計画と根拠資料の接続 | 担当・期限・状態と検証指標を追える。衛星類似度だけで回復策の効果を断定しない |
| P07 | 実測とデモが混ざり、誤って顧客資料に使われる | 証拠内訳と未確認表示、デモ分析の導線整理 | デモ点や未取得値を明示。架空の多軸評価は通常の商談導線で推奨しない |
| P08 | 将来のスマホ記録・同定APIの結果を失わず蓄積したい | メディアと分類・同定結果の拡張契約 | 観測IDとの紐づけ、撮影日時、提供元、判定状態、レビューを分離。未接続APIを動作中と見せない |

## 4. 実施順序と残す機能

1. 変更前のGitタグ・独立bundle・本番Worker版・D1出力を保存。
2. 本計画で既存画面を再評価し、問題と利用動線を記録。
3. P01〜P03を実装、地図操作・小画面・Markdownの安全性を検証して中間保存。
4. P04〜P08のうち現在の基盤で実用にできる保存・根拠・出力フローを実装。追加スキーマは旧版と互換にし、データを削除しない。
5. 顧客の操作順で、拠点→メッシュ→観測→活動→開示準備→出力を実機確認。失敗・空状態も確認。
6. テスト、公開、公開後の動作確認、戻し方と未達事項を記録。

維持する中心機能: プロジェクト、衛星・10mメッシュ、現地調査、回復計画、公開データ照会、LEAPスクリーニング、履歴。削除より導線整理を優先し、既存顧客データは消さない。健康・安全管理や金融機能は、今回の生物多様性の商談目的から分離する。

## 5. 商談で検証すること

15分デモ: 地球から拠点へ→10mの差を選択→生物カードの証拠を確認→次の調査・活動→未対応の開示項目→下書き持ち帰り。公開情報の対象場所とデモ地域を混同しない。

30分ヒアリング: 現行の調査・報告の作業時間、外注費の範囲、意思決定者、継続予算の条件、導入・情報管理条件を確認。効果指標は資料準備時間、重複転記回数、根拠の追跡時間、未確認項目の減少。削減率・契約見込みは測定前に約束しない。

本番の複数企業利用にはテナント分離・契約・データ保管条件・精度検証が必要。今回の商談用改善と、それらを含む一般提供の完成条件は分けて記録する。

| 課題 | 改修・検証 |

追加の評価: 既存LEAP画面はデモを現地記録に数え、衛星類似度から健全性を判定するため、商談で根拠を質問された際の説明に問題があった。今回、この部分を優先して修正した。レポート一覧にも新しい開示・申請準備の入口を追加した。

自動検証: Worker型検査、フロントビルド、27テスト（10mメッシュ、取得処理、権限、開示履歴・競合保存、媒体検証、Markdown安全性、デモ除外等）。Wrangler dry-run成功。大きい地図ライブラリによるバンドル容量の警告は残る。

今回の出力は社内検討用の準備資料であり、TNFDの承認済み開示や自然共生サイトの公式申請書・認定結果ではない。一般提供までの残作業は、企業ごとのデータ分離、実地での精度検証、外部同定・レッドリスト照合、正式様式との対応検証。次の商談ではこれらの要件と、調査・資料準備時間の削減効果を実測する。
